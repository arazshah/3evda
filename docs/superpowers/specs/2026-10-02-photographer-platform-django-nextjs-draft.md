# پلتفرم حرفه‌ای عکاسی سودا رحیم‌پور — طرح اولیه (Django + Next.js + PostgreSQL)

**تاریخ:** 2026-10-02
**وضعیت:** پیش‌نویس — منتظر پاسخ به پرسش‌های بخش ۹
**جایگزین/به‌روزرسانی:** `2026-09-11-3evda-production-cms-design.md` (معماری Next.js تک‌لایه با Drizzle و Better Auth). اگر استک جدید تأیید شود، بخش‌های معماری، احراز هویت و ORM آن سند کنار گذاشته می‌شوند. الزامات امنیتی، دسترس‌پذیری، سئو، بکاپ و استقرار روی Coolify همچنان معتبر می‌مانند.

## ۱. شناخت کسب‌وکار

- **صاحب کار:** سودا رحیم‌پور، عکاس صنعتی و تبلیغاتی (اینستاگرام: `3evda.r`)
- **مشتری‌های هدف:** کارخانه‌ها، برندها، فروشگاه‌های آنلاین، آژانس‌های تبلیغاتی و رستوران‌ها؛ یعنی مشتریان B2B که تصمیم‌گیرنده‌شان معمولاً مدیر بازاریابی یا مدیر برند است.
- **حوزه‌های رایج کار (باید با نمونه‌کارهای واقعی تطبیق داده شود):** عکاسی محصول (پس‌زمینه سفید و صحنه‌آرایی‌شده)، عکاسی صنعتی و کارخانه، خط تولید، معماری و فضای داخلی، پرتره سازمانی، غذا، و کمپین تبلیغاتی.
- **محدودیت این بررسی:** دسترسی به اینستاگرام از محیط توسعه مسدود است. تحلیل دقیق سبک، دسته‌بندی‌ها و رنگ‌بندی برند پس از دریافت نمونه‌ها انجام می‌شود (پرسش ۲).

## ۲. دغدغه‌های یک عکاس صنعتی/تبلیغاتی و پاسخ سامانه

| دغدغه | ماژول پیشنهادی |
|---|---|
| نمایش حرفه‌ای کارها به مشتری سازمانی | پورتفولیو دسته‌بندی‌شده + **کیس‌استادی** (بریف، چالش، راه‌حل، نتیجه، پشت صحنه) |
| دیده‌شدن در گوگل | وبلاگ/مجله، سئوی فنی، Schema، صفحات اختصاصی برای هر خدمت و هر شهر |
| استعلام‌های نامرتب در دایرکت و واتس‌اپ | **فرم استعلام هوشمند** (نوع کار، تعداد محصول، تعداد زاویه، لوکیشن، مهلت) + برآورد خودکار قیمت + پیامک فوری |
| ساخت پیش‌فاکتور | **ابزار ساخت پیش‌فاکتور و قرارداد** با PDF و لینک تأیید آنلاین |
| هماهنگی زمان‌بندی | **تقویم رزرو** (استودیو و لوکیشن)، بستن روزهای پر، یادآور پیامکی |
| تحویل عکس با WeTransfer یا Google Drive | **گالری خصوصی مشتری**: لینک رمزدار، پیش‌نمایش واترمارک‌دار، تاریخ انقضا، دانلود ZIP نسخه نهایی |
| انتخاب عکس و درخواست ادیت از طرف مشتری | **Proofing**: انتخاب، کامنت روی عکس، درخواست ریتاچ، تأیید نهایی، سقف تعداد انتخاب |
| پیگیری پروژه‌ها و مشتری‌ها | **CRM سبک**: شرکت، رابط، تاریخچه پروژه، وضعیت پایپ‌لاین |
| پیگیری پرداخت‌ها | **مالی**: پیش‌پرداخت، اقساط، وضعیت پرداخت، گزارش درآمد، و درگاه پرداخت ایرانی (اختیاری) |
| حق استفاده از تصویر (مخصوص کار تبلیغاتی) | **لایسنس**: مدت، رسانه و محدوده جغرافیایی هر تصویر، با هشدار انقضا |
| کپی‌شدن عکس‌ها | واترمارک خودکار، درج IPTC/کپی‌رایت، حذف GPS از EXIF، جلوگیری از هات‌لینک |
| زمان‌بر بودن به‌روزرسانی سایت | پنل ادمین فارسی با آپلود گروهی، تولید خودکار سایزها (WebP/AVIF) و چیدمان کشیدنی |
| ارتباط با اینستاگرام | ایمپورت دستی/نیمه‌خودکار پست‌ها و لینک‌دادن به پروژه‌ها (در صورت امکان، Graph API) |

## ۳. معماری پیشنهادی

```text
                ┌──────────────── Coolify (Traefik, TLS) ────────────────┐
Browser ──► Next.js (public site SSR/ISR + /panel React dashboard)       │
                │  rewrites /api/* → same origin (cookie + CSRF)         │
                ▼                                                        │
            Django 5.2 LTS + DRF  ──► PostgreSQL 17                     │
                │        └──► Celery workers ◄── Redis (queue/cache)     │
                ▼                    │ image derivatives, watermark, ZIP,│
            MinIO (S3)  ◄────────────┘ SMS/email, reminders, retention   │
                └────────────────────────────────────────────────────────┘
```

- **Backend:** Django 5.2 LTS، Django REST Framework، drf-spectacular (OpenAPI)، django-storages (MinIO)، Pillow/pyvips، Celery + Redis، django-filter، pytest-django.
- **Frontend:** Next.js (App Router) + React + TypeScript strict + Tailwind. سایت عمومی SSR/ISR است و پنل `/panel` مبتنی بر TanStack Query و React Hook Form + Zod. کلاینت API به‌صورت خودکار از OpenAPI تولید می‌شود تا تایپ‌ها بین Django و Next همیشه هم‌خوان بمانند.
- **احراز هویت:** Session کوکی Django (HttpOnly، Secure، SameSite=Lax) + CSRF روی یک دامنه از طریق rewrite در Next. ورود دومرحله‌ای (TOTP) برای ادمین. مشتری‌ها حساب کاربری ندارند و با لینک امضاشده + رمز/OTP پیامکی وارد گالری خود می‌شوند.
- **Django Admin:** فقط برای عملیات فنی و پشتیبانی، پشت مسیر مخفی و MFA. پنل اصلی صاحب کار در Next.js و هم‌سبک با برند ساخته می‌شود.
- **ساختار مخزن (monorepo):**
  ```text
  backend/   (Django project: config/, apps/{core,cms,portfolio,blog,leads,crm,projects,
              booking,galleries,finance,licensing,media,notifications,audit})
  frontend/  (Next.js: app/(site), app/panel, app/g/[token] client gallery)
  infra/     (docker-compose.dev.yml, Dockerfiles, Coolify docs, backup scripts)
  docs/
  ```

## ۴. مدل داده (خلاصه)

- **cms:** SiteSettings، Page، Section، NavItem، SocialLink، Metric، FAQ، Testimonial، ClientLogo، Service، Package
- **portfolio:** Category، Project (کیس‌استادی)، ProjectImage، Tag، BeforeAfter
- **blog:** Article، ArticleCategory، SlugRedirect
- **media:** Asset (اصل خصوصی)، Variant (WebP/AVIF، واترمارک)، Reference
- **leads:** Inquiry، InquiryNote، StatusHistory، QuoteRule (قواعد برآورد قیمت)
- **crm:** Company، Contact
- **projects:** Job (پروژه سفارش)، ShotListItem، Brief/Moodboard attachment
- **booking:** Availability، BlockedSlot، Booking
- **galleries:** ClientGallery (توکن، رمز، انقضا، سقف انتخاب، اجازه دانلود)، GalleryImage، Selection، Comment، RetouchRequest، DownloadLog
- **finance:** Quote/Proforma، Invoice، LineItem، Payment، Contract (PDF + تأیید آنلاین)
- **licensing:** UsageLicense (تصویر/پروژه، رسانه، مدت، منطقه، انقضا)
- **notifications:** Outbox، Delivery، Template (SMS.ir/کاوه‌نگار، ایمیل، و بعداً تلگرام/بله/واتس‌اپ)
- **audit:** AuditLog

## ۵. فازبندی تحویل

| فاز | محتوا | خروجی قابل استفاده |
|---|---|---|
| **0. زیرساخت** | Monorepo، Docker Compose (Postgres، Redis، MinIO)، CI، لینت و تست، Health check | محیط توسعه و CI سبز |

| **2. سایت عمومی + CMS (MVP)** | خانه، درباره، خدمات، پورتفولیو و کیس‌استادی، مشتریان، نظرات، FAQ، تماس + پنل مدیریت همه‌شان | **سایت قابل انتشار** |
| **3. استعلام و پیش‌فاکتور** | فرم هوشمند، برآورد قیمت، اعلان پیامکی، پایپ‌لاین سرنخ، پیش‌فاکتور PDF | جذب و پیگیری مشتری |

| **5. CRM، پروژه و رزرو** | شرکت‌ها، پروژه‌ها، شات‌لیست، تقویم، یادآورها | مدیریت روزانه کار |
| **6. مالی و لایسنس** | فاکتور، پرداخت‌ها، درگاه (اختیاری)، قرارداد، لایسنس تصاویر، گزارش‌ها | کنترل درآمد و حقوق تصویر |
| **7. بلاگ و سئوی پیشرفته** | مجله، Schema، سایت‌مپ، ریدایرکت، صفحات خدمت-شهر، انگلیسی (اختیاری) | رشد ارگانیک |
| **8. سخت‌سازی و انتشار** | CSP، بکاپ/ریستور، مانیتورینگ، Lighthouse ≥ ۹۰، ران‌بوک Coolify | تحویل نهایی |

هر فاز با گیت کیفیت بسته می‌شود: تست‌های واحد و یکپارچه (pytest، Vitest)، E2E (Playwright)، دسترس‌پذیری (axe) و بیلد Docker.

## ۶. طراحی بصری

- راست‌چین فارسی، فونت وزیرمتن یا یکان‌بخ (self-hosted)، تصویرمحور با فضای منفی زیاد. در عکاسی صنعتی، خود عکس‌ها هویت سایت هستند.
- تم پیشنهادی: تیره/خنثی با یک رنگ تأکیدی برند. اگر هویت قبلی (`Sevda.html`، تم تیره و طلایی) مدنظر است، همان حفظ می‌شود (پرسش ۱).
- گالری Masonry/Justified با Lightbox، اسلایدر قبل/بعد ریتاچ، و بارگذاری تدریجی blur-up.

## ۷. نکات فنی مهم

- **محل سرور:** اگر سرور خارج از ایران باشد، پیامک ایرانی و درگاه پرداخت ممکن است محدودیت IP داشته باشند. اگر داخل ایران باشد، دسترسی به npm، Docker Hub و Instagram API محدود است. این مورد روی طراحی اعلان‌ها و CI اثر مستقیم دارد.
- **Instagram Graph API** به حساب Business/Creator و اپ Meta نیاز دارد و از سرور ایران کار نمی‌کند. برای همین «ایمپورت دستی» پیش‌فرض است.
- فایل‌های اصلی عکس (RAW/TIFF/JPEG حجیم) هیچ‌وقت عمومی نیستند و دانلود فقط با لینک موقت امضاشده انجام می‌شود.

## ۸. ریسک‌ها

- حجم بالای فایل‌های گالری مشتری (فضای دیسک MinIO و پهنای باند). راه‌حل: سهمیه، انقضای خودکار و آرشیو سرد.
- دو سرویس (Django و Next) پیچیدگی استقرار را بیشتر می‌کند. راه‌حل: Compose یکسان در توسعه و Coolify و قرارداد API تولیدشده از OpenAPI.

## ۹. پرسش‌های باز

1. **تغییر استک:** سند قبلی Next.js تک‌لایه را تأیید کرده بود. آیا قطعاً به Django + Next.js تغییر می‌دهیم؟ آیا طراحی `Sevda.html` (تیره/طلایی) حفظ شود؟ این فایل در مخزن نیست.
2. **نمونه‌کارها:** اسکرین‌شات پروفایل اینستاگرام، یا خروجی دانلود داده اینستاگرام، یا پوشه‌ای از ۲۰ تا ۵۰ عکس منتخب به‌همراه دسته‌بندی‌ها.
3. **اولویت ماژول‌ها:** کدام‌یک در نسخه اول لازم است؟ (گالری مشتری، رزرو، پیش‌فاکتور، فاکتور و پرداخت آنلاین، لایسنس)
4. **زبان سایت:** فقط فارسی، یا فارسی + انگلیسی برای مشتریان خارجی/صادراتی؟
5. **سرور و دامنه:** Coolify داخل ایران است یا خارج؟ دامنه چیست؟
6. **کاربران پنل:** فقط خود ایشان، یا دستیار/ادیتور هم دسترسی محدود لازم دارد؟
7. **اعلان‌ها:** SMS.ir، کاوه‌نگار، یا ربات تلگرام/بله؟
8. **قیمت‌گذاری:** آیا قیمت پکیج‌ها روی سایت عمومی نمایش داده شود یا فقط «استعلام قیمت»؟
9. **هویت برند:** لوگو، رنگ و فونت موجود است یا باید طراحی شود؟
