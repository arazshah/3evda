# فاز ۶ — گالری مشتری و Proofing (برنامه‌ی تفصیلی)

**هدف:** همسرتان بعد از جلسه یک گالری خصوصی می‌سازد، صدها عکس را یک‌جا آپلود می‌کند و لینکش را برای مشتری می‌فرستد. مشتری روی پیش‌نمایش واترمارک‌دار عکس‌ها را انتخاب می‌کند، برای هر عکس توضیح یا درخواست ریتاچ می‌نویسد، انتخابش را نهایی می‌کند (قفل می‌شود) و در سطحی که صاحب‌کار اجازه داده دانلود می‌کند. همسرتان انتخاب‌ها را می‌بیند، نام فایل‌ها را برای Lightroom کپی می‌کند، نسخه‌های نهایی را آپلود می‌کند و لاگ دانلود را می‌بیند.
**سند طراحی:** `docs/superpowers/specs/2026-10-02-photographer-platform-design.md`، **نقشه‌ی راه:** `docs/superpowers/plans/2026-10-02-roadmap.md` (فاز ۶)

## تصمیم‌های این فاز

| موضوع | تصمیم |
|---|---|
| جدا از کتابخانه‌ی رسانه | عکس‌های مشتری **هیچ‌وقت** وارد کتابخانه‌ی رسانه‌ی سایت نمی‌شوند: آنجا نسخه‌ها در باکت **عمومی** است. گالری مدل و مسیر پردازش خودش را دارد و همه‌ی فایل‌هایش (اصل، پیش‌نمایش، نهایی، ZIP) در باکت **خصوصی** است. هیچ آدرس عمومی برای عکس مشتری وجود ندارد |
| مدل‌ها | `Gallery` (عنوان، نام مشتری، زبان، `public_id`، رمز اختیاری به‌صورت هش، `expires_at`، `selection_limit`، `download_level`، `status`، اتصال اختیاری به استعلام/رزرو/پیش‌فاکتور، `link_version`)، `GalleryPhoto` (اصل در باکت خصوصی، نام فایل اصلی، ابعاد، پیش‌نمایش، ترتیب، وضعیت پردازش)، `Selection` (انتخاب‌شده، توضیح، درخواست ریتاچ)، `FinalFile` (نسخه‌ی نهایی تحویلی)، `DownloadLog`، `ZipJob` |
| وضعیت گالری | `پیش‌نویس ← منتشرشده ← نهایی‌شده (قفل) ← بایگانی`؛ `منقضی` از روی `expires_at` هنگام خواندن محاسبه می‌شود (مثل پیش‌فاکتور، بدون زمان‌بند). صاحب‌کار می‌تواند نهایی‌شده را دوباره باز کند |
| لینک | `/g/<public_id>_<امضا>` (HMAC قطعی، بدون نقطه، با نسخه‌ی لینک برای ابطال؛ مثل پیش‌فاکتور و رزرو). `noindex`، `no-store`، دوزبانه |
| رمز | اختیاری. هش با هشر Django (`make_password`)، سنجش با `check_password`. بعد از رمز درست، سرور یک **توکن دسترسی کوتاه‌عمر** (HMAC با زمان انقضا، ۱۲ ساعت، مخصوص همان گالری) می‌دهد که مرورگر در `sessionStorage` نگه می‌دارد و با هدر می‌فرستد؛ بدون رمز یا توکن، هیچ داده‌ای (حتی فهرست عکس) داده نمی‌شود. **جلوگیری از حدس رمز:** حداکثر ۵ تلاش اشتباه در ۱۵ دقیقه برای هر (گالری، IP هش‌شده) و ۳۰ تلاش برای هر گالری در ساعت، بعدش `429`؛ پاسخ رمز اشتباه و گالری ناموجود هم‌شکل است |
| پیش‌نمایش | هنگام آپلود، worker دو نسخه‌ی **واترمارک‌دار** می‌سازد: بندانگشتی (۶۰۰) و نمایش (۲۰۰۰ ضلع بلند) با واترمارک صاحب‌کار (همان تنظیمات پنل)، فرمت WebP، متادیتا (EXIF/GPS) حذف‌شده. مشتری فقط همین‌ها را می‌بیند |
| ارائه‌ی فایل | همه‌ی فایل‌ها با **لینک امضاشده‌ی کوتاه‌مدت** از مسیر `/storage-signed` (مثل پیوست استعلام) تحویل می‌شوند: پیش‌نمایش‌ها ۵ دقیقه، دانلود ۶۰ ثانیه، `Content-Disposition: attachment` برای دانلود. اصل بدون امضا و بدون سطح دانلودِ مجاز هرگز در دسترس نیست |
| آپلود گروهی | چندین فایل هم‌زمان با صف و نوار پیشرفت (حداکثر ۳ آپلود هم‌زمان)، تکرار خودکار فایل ناموفق، تشخیص تکراری با `sha256` درون همان گالری، اعتبارسنجی magic bytes، سقف حجم هر فایل (۸۰ مگابایت) و سقف تعداد هر گالری (۱۰۰۰). پردازش پیش‌نمایش در worker و صف جدا از پردازش سایت تا آپلود گالری سایت را کند نکند |
| انتخاب | `PUT` تکی و idempotent. سقف انتخاب **در سرور** و زیر قفل ردیف گالری سنجیده می‌شود (دو درخواست هم‌زمان نمی‌توانند از سقف بگذرند). توضیح هر عکس تا ۵۰۰ نویسه (متن ساده، همیشه escape‌شده). «درخواست ریتاچ» یک پرچم جدا از انتخاب است |
| نهایی کردن | مشتری «ارسال نهایی» را می‌زند ← وضعیت قفل می‌شود و هر تغییر بعدی `409` می‌گیرد؛ زمان و IP هش‌شده ثبت می‌شود. تکرار همان ارسال بی‌اثر است |
| سطح دانلود | `none` (فقط دیدن)، `selected` (انتخاب‌ها با اندازه‌ی نمایش)، `all_web` (همه با اندازه‌ی نمایش)، `original` (انتخاب‌ها یا همه با اصل). تغییر سطح فوراً اثر می‌کند. نسخه‌های نهایی تحویلی همیشه برای مشتری قابل دانلودند |
| ZIP | ساخت در worker (استریم از باکت خصوصی به یک فایل ZIP در باکت خصوصی، بدون بارگیری همه‌چیز در حافظه)، `ZipJob` با وضعیت و درصد، مشتری با polling پیشرفت را می‌بیند و وقتی آماده شد لینک امضاشده‌ی ۶۰ ثانیه‌ای می‌گیرد. ZIP‌ها ۲۴ ساعت می‌مانند؛ پاک‌سازی تنبل هنگام درخواست بعدی + دستور مدیریتی (زمان‌بندی خودکار در فاز ۷). سقف: یک ZIP هم‌زمان برای هر گالری |
| لاگ دانلود | هر دانلود (تکی/ZIP) با زمان، نوع، تعداد فایل و IP هش‌شده؛ در پنل دیده می‌شود |
| پنل | فهرست گالری‌ها (مصرف فضا)، ساخت و ویرایش، آپلود گروهی، ترتیب با دکمه، حذف عکس، نمای انتخاب‌ها (شمارش، توضیح‌ها، فیلتر «انتخاب‌شده / ریتاچ»)، **کپی نام فایل‌ها برای Lightroom** (فهرست جداشده با کاما، آماده‌ی جست‌وجوی Filename)، آپلود نسخه‌های نهایی، لاگ دانلود، لینک (کپی / لینک تازه)، بازکردن دوباره، بایگانی و حذف (فایل‌ها هم پاک می‌شوند) |
| مصرف فضا | جمع حجم اصل‌ها + پیش‌نمایش‌ها + ZIP‌ها برای هر گالری و کل، در پنل |
| حذف و نگهداری | حذف گالری فایل‌ها را از باکت خصوصی هم پاک می‌کند (در worker، با تلاش مجدد). حذف یا ناشناس‌سازی خودکار گالری‌های منقضی‌شده‌ی قدیمی در فاز ۷ (سیاست نگهداری) |
| بدون | حساب کاربری مشتری، پرداخت، اعلان، چاپ سفارشی، ویرایش آنلاین عکس |

| `POST /api/admin/galleries/{id}/photos/` | آپلود یک عکس (چندین فراخوانی هم‌زمان از مرورگر)؛ `409` برای تکراری |
| `PATCH /api/admin/galleries/{id}/photos/order/` ، `DELETE …/photos/{pid}/` | ترتیب و حذف |
| `GET /api/admin/galleries/{id}/selections/` | انتخاب‌ها با توضیح و ریتاچ و نام فایل‌ها |
| `POST /api/admin/galleries/{id}/finals/` | آپلود نسخه‌ی نهایی تحویلی |
| `POST /api/admin/galleries/{id}/publish|reopen|archive|new-link/` | تغییر وضعیت |
| `GET /api/admin/galleries/{id}/downloads/` | لاگ دانلود |

## آزمون‌ها

- دسترسی: لینک جعلی، نسخه‌ی باطل‌شده، منقضی، گالری پیش‌نویس، رمز اشتباه/درست، **حدس رمز** (سقف تلاش، همان پاسخِ گالری ناموجود)، توکن دسترسی منقضی یا برای گالری دیگر، گالری یک مشتری برای مشتری دیگر
- فایل: **اصل بدون امضا یا بدون سطح دانلود در دسترس نیست**، لینک امضاشده بعد از انقضا کار نمی‌کند، آدرس عمومی برای عکس وجود ندارد (باکت عمومی خالی از عکس مشتری)، پیش‌نمایش واترمارک‌دار و بدون EXIF
- انتخاب: سقف تحت درخواست‌های هم‌زمان (thread + `transaction=True`)، قفل بعد از ارسال نهایی، idempotent بودن، توضیح escape‌شده (XSS)، بازکردن دوباره
- ZIP: کامل و درست (همه‌ی فایل‌ها، نام‌ها، بدون تکرار)، یک ZIP هم‌زمان، پیشرفت، انقضا و پاک‌سازی، سطح‌های دانلود
- آپلود: magic bytes، تکراری، سقف حجم و تعداد، شکست و تلاش مجدد، پاک شدن فایل‌ها با حذف گالری
- E2E: ساخت گالری ← آپلود چند عکس ← لینک ← مشتری (با رمز) انتخاب و توضیح و ارسال ← صاحب‌کار انتخاب‌ها و نام فایل‌ها را می‌بیند ← مشتری ZIP می‌گیرد؛ axe، موبایل
- بار: ۵۰۰ عکس (فهرست، لینک‌های امضاشده، ZIP) در زمان و حافظه‌ی معقول
**گیت:** همه‌ی CI سبز.

## ورودی از صاحب‌کار (غیرمسدودکننده)
متن واترمارک و جای آن (فعلاً همان تنظیم پنل)، سقف پیش‌فرض انتخاب، سطح دانلود پیش‌فرض، مدت انقضای پیش‌فرض گالری. تا آن موقع مقدارهای پیش‌فرض: ۳۰ روز انقضا، سطح «انتخاب‌ها با اندازه‌ی نمایش»، بدون سقف انتخاب.
