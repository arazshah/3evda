# فاز ۳ — بلاگ و سئو (برنامه‌ی تفصیلی)

**هدف:** مجله‌ی دوزبانه‌ای که همسرتان خودش از پنل می‌نویسد و منتشر می‌کند، و سئوی فنی کامل برای کل سایت (sitemap، robots، RSS، داده‌ی ساختاریافته، ریدایرکت‌ها).
**سند طراحی:** `docs/superpowers/specs/2026-10-02-photographer-platform-design.md` (بخش ۵.۶)، **نقشه‌ی راه:** `docs/superpowers/plans/2026-10-02-roadmap.md` (فاز ۳)

## تصمیم‌های این فاز

| موضوع | تصمیم |
|---|---|
| نشانی‌ها | فهرست در `/blog` و مقاله در `/blog/<slug>` (انگلیسی: `/en/blog/...`). برچسب منو «مجله» / «Journal». دسته در `/blog/category/<slug>` و برچسب در `/blog/tag/<slug>` |
| مقاله در دو زبان | برای هر زبان یک رکورد جدا؛ نسخه‌های fa و en با `translation_group` به هم وصل می‌شوند. مقاله‌ای که ترجمه ندارد فقط در زبان خودش منتشر می‌شود و `hreflang` فقط به نسخه‌های واقعاً موجود اشاره می‌کند (نه به صفحه‌ی ۴۰۴) |
| بدنه‌ی مقاله | ویرایشگر TipTap در پنل؛ **JSON ساختاریافته منبع حقیقت است**. سرور هنگام خواندن آن را با فهرست مجاز گره‌ها و مارک‌ها (پاراگراف، تیتر ۲ تا ۴، فهرست، نقل‌قول، خط جداکننده، تصویر، پیوند، پررنگ، کج، کد) به HTML تبدیل می‌کند و خروجی را دوباره با `nh3` پاک‌سازی می‌کند (دفاع دوم). HTML خام از کلاینت هرگز پذیرفته نمی‌شود. پیوندها فقط `http(s)`، `mailto` و مسیر نسبی |
| تصویر داخل متن | از کتابخانه‌ی Media انتخاب می‌شود و با شناسه ذخیره می‌شود نه آدرس. **ارجاع‌ها هنگام ذخیره‌ی مقاله و در همان تراکنش همگام می‌شوند:** شناسه‌ی همه‌ی تصویرهای بدنه استخراج می‌شود، تصویر ناموجود یا آماده‌نشده رد می‌شود، `MediaReference` ساخته و ارجاع تصویرهای حذف‌شده از متن پاک می‌شود (پس فایلِ در حال استفاده هیچ‌وقت قابل حذف نیست و فایل حذف‌نشده‌ای از متن ویرایش‌شده جا نمی‌ماند). رندر فقط‌خواندنی است: `srcset` و متن جایگزین را از خود رسانه می‌سازد و چیزی نمی‌نویسد |
| انتشار زمان‌بندی‌شده | **بدون Celery beat، بدون سرویس جدید و بدون راز اشتراکی:** مقاله‌ای عمومی است که `published_at ≤ اکنون` باشد؛ «زمان‌بندی‌شده» همان منتشرشده با تاریخ آینده است. برای اینکه ظهور آن در لحظه‌ی خودش **تضمین** شود (و به ترافیک سایت بستگی نداشته باشد): (۱) صفحه‌های مجله داده را با `cache: "no-store"` از API می‌گیرند، نه از کش داده‌ی Next که اول داده‌ی کهنه می‌دهد؛ (۲) خود Django پاسخ‌های عمومی مجله را در Redis کش می‌کند با TTL برابر `min(۳۰ ثانیه، زمان تا نزدیک‌ترین انتشار زمان‌بندی‌شده)`، پس هیچ ورودی کش از لحظه‌ی انتشار جلوتر نمی‌ماند؛ (۳) هر ذخیره، انتشار یا حذف در پنل نسخه‌ی کش را بالا می‌برد و فوراً اعمال می‌شود. بدهی این روش: وقتی API در دسترس نباشد صفحه‌های مجله آخرین نسخه‌ی کش‌شده را ندارند (بقیه‌ی سایت دارد) |
| پیش‌نویس | هرگز در API عمومی، sitemap، RSS یا نتایج فهرست نیست. پیش‌نمایش با لینک امضاشده‌ی موقت (۲۴ ساعت) روی `/blog/preview/<token>`، با `noindex` و `Cache-Control: no-store` |
| تغییر slug | هر slug قبلی در جدول ریدایرکت می‌ماند و به slug جدید `۳۰۱` می‌دهد (برای دو زبان جدا). slug یکتا در هر زبان است |
| زمان مطالعه | خودکار از شمار کلمات متن (فارسی و انگلیسی)، هنگام ذخیره |
| سئو | عنوان و توضیح هر مقاله اختیاری است و به‌طور پیش‌فرض از عنوان و خلاصه ساخته می‌شود. تصویر OG: تصویر OG مقاله ← کاور ← تصویر OG سایت. تصویر OG خودکار (کارت با عنوان) فقط اگر متن فارسی درست شکل بگیرد (به «ریسک‌ها» نگاه کنید) |
| نمونه برای CI | دستور `seed_blog_demo` یک مقاله‌ی منتشرشده می‌سازد تا Lighthouse و e2e صفحه‌ی مقاله را ببینند؛ در پروداکشن اجرا نمی‌شود |
| خارج از این فاز | نظرات خوانندگان، جست‌وجوی متنی مقالات و خبرنامه (نسخه‌ی ۱ ندارد) |

## APIهای بخش ۳.۱

| متد و مسیر | توضیح |
|---|---|
| `GET /api/public/blog/articles?lang=&category=&tag=&page=` | بدون ورود؛ فقط منتشرشده‌ها (`published_at ≤ اکنون`)، تازه‌ترین اول؛ هر مورد: عنوان، slug، خلاصه، کاور، دسته، برچسب‌ها، زمان مطالعه، تاریخ |
| `GET /api/public/blog/articles/{lang}/{slug}` | جزئیات با بدنه‌ی HTML امن، فیلدهای SEO، ترجمه‌ها (`alternates`)، مقالات و پروژه‌های مرتبط، قبلی و بعدی. اگر slug قدیمی باشد `301` با `Location` به slug جدید |
| `GET /api/public/blog/taxonomy?lang=` | `lang` الزامی است؛ فقط دسته‌ها و برچسب‌هایی که **در همان زبان** مقاله‌ی منتشرشده دارند، با شمار همان زبان (دسته‌ای که فقط مقاله‌ی انگلیسی دارد در مجله‌ی فارسی دیده نمی‌شود و به فهرست خالی نمی‌رسد) |
| `GET /api/public/blog/preview/{token}` | پیش‌نویس با توکن امضاشده؛ `no-store` |
| `GET /api/public/sitemap` | فهرست خام نشانی‌ها برای ساخت sitemap در Next (در ۳.۴) |
| `GET/POST/PATCH/DELETE /api/admin/blog/articles/` | CRUD مقاله؛ `body` به‌صورت JSON؛ فیلترها: وضعیت، زبان، دسته |
| `POST /api/admin/blog/articles/{id}/preview-link/` | ساخت لینک پیش‌نمایش امضاشده |
| `POST /api/admin/blog/articles/{id}/translate/` | ساخت نسخه‌ی زبان دیگر (پیش‌نویس، هم‌گروه) |
| `GET/POST/PATCH/DELETE /api/admin/blog/categories/` و `/tags/` | دسته و برچسب (دوزبانه) |

## ریسک‌ها و راه‌حل

| ریسک | راه‌حل |
|---|---|
| تصویر OG خودکار با متن فارسی: برخی ابزارهای رندر حروف عربی را درست به هم نمی‌چسبانند | یک spike کوتاه در ۳.۴؛ اگر درست نشد، از کاور یا تصویر OG سایت استفاده می‌کنیم و این مورد به فاز بعد می‌رود. هیچ صفحه‌ای بدون تصویر OG نمی‌ماند |
| XSS از بدنه‌ی مقاله | رندر فقط از JSON با فهرست مجاز، سپس `nh3`؛ تست‌های حمله (اسکریپت، `javascript:`، `onerror`، گره‌ی ناشناخته) |
| مقاله‌ی زمان‌بندی‌شده دیر ظاهر شود یا زودتر | TTL کش Django حداکثر تا نزدیک‌ترین زمان انتشار؛ Next بدون کش؛ تست با ساعت جعلی در لحظه‌ی قبل و بعد از `published_at` و تست اینکه ذخیره‌ی پنل کش را باطل می‌کند |
| وابستگی‌های جدید (`nh3`، TipTap) | نسخه‌ی دقیق و hash در `requirements.txt` و lockfile؛ `pip-audit` و `pnpm audit` در CI |
| ریدایرکت‌ها زنجیره یا حلقه بسازند | هنگام ساخت ریدایرکت، ریدایرکت‌های قبلی همان مقاله مستقیم به slug فعلی اشاره می‌کنند؛ slug فعلی هرگز در جدول ریدایرکت نمی‌ماند |

## گیت تکمیل فاز ۳

- پیش‌نویس هرگز عمومی یا در sitemap و RSS نیست؛ انتشار زمان‌بندی‌شده دقیقاً در لحظه‌ی خودش ظاهر می‌شود (حتی بدون هیچ بازدیدی قبل از آن)؛ ارجاع رسانه‌ی تصویرهای بدنه هنگام ذخیره ثبت و با ویرایش پاک می‌شود
- XSS در بدنه‌ی مقاله پاک می‌شود؛ ریدایرکت slug کار می‌کند
- snapshot متادیتا و Schema؛ اعتبارسنجی ساختار sitemap و RSS
- E2E: نوشتن در پنل ← پیش‌نمایش ← انتشار ← دیدن در سایت و در sitemap و RSS ← تغییر slug و ریدایرکت ← حذف
- همه‌ی چک‌های CI سبز؛ Lighthouse SEO ≥ ۹۵ روی صفحه‌ی مقاله و ≥ ۹۰ روی بقیه
