# ADR 0001: سرویس ذخیره‌سازی فایل (S3)

- **تاریخ:** 2026-10-02
- **وضعیت:** پذیرفته‌شده

## زمینه

عکس‌های اصلی، واریانت‌های وب، فایل‌های گالری مشتری و ZIPها باید روی همان سرور Coolify (داخل ایران) نگهداری شوند. کد فقط از رابط S3 (django-storages + boto3) استفاده می‌کند تا سرویس قابل تعویض باشد. نیازها:

- اجرای پایدار روی یک سرور و در یک کانتینر
- presigned URL برای فایل‌های خصوصی
- خواندن ناشناس فقط برای bucket عمومی، بدون امکان فهرست‌گیری یا نوشتن
- ایمیج رسمی، فعال و قابل pin
- بکاپ ساده

## گزینه‌ها

| گزینه | وضعیت (اکتبر ۲۰۲۶) | نتیجه |
|---|---|---|
| MinIO Community | نسخه‌ی Community دیگر ایمیج رسمی به‌روز روی Docker Hub منتشر نمی‌کند (`minio/minio` از محیط CI قابل pull نبود) و کنسول مدیریتی‌اش محدود شده | رد شد: بدون به‌روزرسانی امنیتی |
| Garage | متن‌باز و فعال؛ ولی بعد از اولین اجرا به چند فرمان CLI برای layout و ساخت کلید نیاز دارد و کار در compose پیچیده‌تر می‌شود | گزینه‌ی دوم |
| **SeaweedFS** | متن‌باز (Apache-2.0)، انتشار مرتب (نسخه‌ی 4.48، سپتامبر ۲۰۲۶)، و یک فرمان `weed server -s3` برای single-node | **انتخاب شد** |
| فایل‌سیستم محلی | ساده‌ترین گزینه، ولی presigned URL ندارد و ارسال فایل به کاربر از مسیر Django می‌گذرد | رد شد |

## تصمیم

`chrislusf/seaweedfs:4.48` در حالت `server -s3`، با یک volume نام‌دار (`objects`).

- فایل `s3.json` هنگام شروع کانتینر از متغیرهای محیطی ساخته می‌شود، پس هیچ کلیدی در مخزن نیست. شامل دو identity است:
  - `app`: دسترسی کامل، با `S3_ACCESS_KEY` و `S3_SECRET_KEY`
  - `anonymous`: فقط `Read:<S3_PUBLIC_BUCKET>`
- bucketها با دستور `manage.py ensure_buckets` در entrypoint سرویس api ساخته می‌شوند (idempotent).
- gateway مسیر `/media/*` را به `storage:8333/<public-bucket>/*` می‌فرستد و هیچ مسیری به bucket خصوصی ندارد.

**تأییدشده با تست واقعی روی ایمیج 4.48:**
- ساخت idempotent هر دو bucket
- `head_bucket` برای health check
- آپلود و دانلود با django-storages
- دریافت فایل خصوصی با presigned URL
- خواندن ناشناس bucket خصوصی ← 403
- خواندن ناشناس bucket عمومی ← 200
- PUT ناشناس ← 403
- فهرست‌گیری ناشناس ← 403

## پیامدها

- **presigned URLها** با آدرس داخلی (`storage:8333`) امضا می‌شوند و از مرورگر قابل استفاده نیستند. در فاز ۱ (Media) یکی از این دو راه انتخاب می‌شود:
  - یک endpoint عمومی جداگانه برای S3 (مثلاً `files.3evda.com`)
  - ارسال فایل خصوصی از طریق Django با `X-Accel-Redirect` در gateway

  تا آن زمان هیچ قابلیتی به URL امضاشده‌ی خصوصی وابسته نیست.
- **بکاپ** با `weed backup` یا کپی همگام‌سازی‌شده‌ی volume در فاز ۷.
- **تعویض سرویس** فقط به تغییر سرویس `storage` در compose و متغیرهای `S3_*` نیاز دارد.
